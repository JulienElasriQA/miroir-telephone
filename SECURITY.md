# Sécurité

## Signaler une vulnérabilité

Merci de **ne pas ouvrir d'issue publique**. Utilisez le signalement privé de GitHub : onglet **Security → Report a vulnerability** de ce dépôt.

## Points d'attention

- **Mode sans fil (Android)** : adb écoute sur le port 5555 du réseau Wi-Fi. Chaque nouvel ordinateur doit être autorisé sur le téléphone, mais ce mode est à éviter sur un réseau public. Recliquez sur le bouton ou redémarrez le téléphone pour le couper.
- **Partage sur le réseau local** : la commande copiée donne à un collègue le contrôle complet du téléphone. Ne la partagez qu'avec des personnes de confiance.
- **Exécutables Windows / Linux** : ils ne sont pas signés. Téléchargez-les uniquement depuis les Releases de ce dépôt ; ils sont construits par GitHub Actions à partir des sources.
- **scrcpy** : l'installation automatique télécharge la version officielle depuis GitHub et vérifie sa somme SHA-256.
- **PIN du téléphone** : enregistré dans le trousseau macOS (service `miroir-telephone-pin`, compte = numéro de série), écrit via `security -i` (valeur lue sur l'entrée standard, absente des arguments visibles par `ps`). Au déverrouillage, le runner le lit en mémoire et le transmet à `adb shell` par l'entrée standard (`print -r -- "input text …" | adb shell`) : il n'apparaît dans aucun argument de commande sur le Mac. En revanche, il est visible un instant dans la liste des processus **du téléphone** (la commande `input text` y tourne le temps de la saisie). Il n'est écrit ni dans un fichier, ni dans le prompt, ni dans les journaux ou le rapport. Limite : le trousseau est lisible **sans invite** par les processus de votre session (le binaire `security` est de confiance pour cet élément) ; un logiciel malveillant tournant sous votre compte pourrait donc le lire.
- **Test automatique : ce que l'agent peut et ne peut pas faire.** L'agent Claude Code est lancé sans réglages utilisateur, projet ni local (donc sans hooks ni plugins), sans serveur MCP et avec seulement les outils `Bash` et `Read`. Il peut : exécuter `adb -s <serial> shell …` et `adb -s <serial> exec-out …` (actions sur le téléphone), lancer `ecran.sh` et `capture.sh` (copiés en lecture seule dans le dossier de travail du test), lire les fichiers du dossier de travail. Il ne peut pas : `adb push`, `pull`, `install`, `connect`, `forward`, `reverse`, `tcpip`, ni `-H` / `-P` ; lire des fichiers hors du dossier de travail ; écrire ou modifier des fichiers du Mac (pas d'outil d'édition, et `ecran.sh` / `capture.sh` sont à chemin fixe, avec une validation stricte de leurs paramètres) ; lire le trousseau. Les commandes destructrices sont interdites à l'agent : `pm uninstall`, `pm clear`, `cmd package uninstall`, `rm`, `reboot`, `svc`, `settings put`, `am force-stop` (en `shell` et en `exec-out`), ainsi que `adb root`, `remount`, `reboot`, `uninstall` et `sideload`. Cette liste n'est pas exhaustive (une commande déguisée, par exemple passée entre guillemets ou via un autre binaire, peut passer). Il reste en revanche maître du téléphone : il peut y faire ce que `adb shell` permet (le texte de la consigne l'interdit pour les actions irréversibles, mais ce n'est pas une garantie technique).
- **Injection par le contenu** : le texte de la consigne, le texte affiché sur le téléphone (messages, pages web, notifications) et le contenu des cas de test Squash (rejoués par « Rejouer la sélection ») sont des données non fiables. Un texte hostile affiché à l'écran peut tenter de détourner l'agent. Le prompt encadre la consigne par des balises `<consigne>` et demande de la traiter comme une donnée, ce qui réduit le risque sans l'éliminer ; les restrictions d'outils ci-dessus limitent les dégâts au téléphone de test. Utilisez un téléphone de test sans compte ni donnée personnelle.
- **Consigne conservée en clair** : le texte de la consigne est gardé dans les préférences de l'app (`lastTest`), dans le dossier de cache `~/Library/Caches/MiroirTelephone/tests/` (dossiers en 700) et dans `rapport.txt`. Ne mettez jamais de code ni de mot de passe dedans : l'app refuse de lancer une consigne qui ressemble à un code (« pin », « code », « mot de passe »… suivi de 4 à 16 chiffres) et ne la sauvegarde pas.
- **Micro du Mac (vidéos Android)** : le son du micro n'est jamais envoyé à l'IA ni à aucun serveur : il reste en local, dans la vidéo. Quand le micro est actif, scrcpy écrit la vidéo et ffmpeg le m4a dans le cache `~/Library/Caches/MiroirTelephone/micro/` (dossier en 700, créé seulement si aucun composant du chemin (`Library`, `Caches`, `MiroirTelephone`, dossier) n'est un lien symbolique et si son chemin réel est exactement `~/Library/Caches/MiroirTelephone/…`, comme pour le cache Squash ; fichiers du micro créés en 600 via `umask 077`), et la fusion se fait entièrement dans ce cache. Le dossier de sortie ne reçoit qu'**une seule création** : la copie du fichier final `Android_<date>.mp4` (taille vérifiée), puis le cache est nettoyé ; l'app n'y renomme ni ne supprime rien et n'y laisse ni fichier caché ni `_micro.m4a`. Si la fusion échoue (nouvel essai avec un filtre plus simple), la vidéo seule est livrée et le m4a de repli **reste dans le cache** ; si la copie finale est impossible (destination déjà existante ou lien, lecture seule, disque plein), rien n'est écrasé (création atomique en `noclobber`, qui refuse aussi un lien, même cassé, sans écrire sa cible) et la vidéo fusionnée reste 24 h dans le cache (voix 7 jours), avec son chemin dans le statut (un éventuel fichier partiel laissé par `cp` est signalé, jamais supprimé) ; le stderr de ffmpeg est conservé dans `fusion_<date>.log` (supprimé en cas de succès ; il ne contient ni secret ni son). Le journal du micro (`micro_*.log`), le fichier de décalage (`temps_*.txt`, écrit par un petit watcher perl arrêté en même temps que l'enregistrement) et le résultat de fusion (`micro_*.res`) sont supprimés à l'arrêt. Purge au démarrage suivant, uniquement directement sous ce dossier : fichiers temporaires (`video_*.mp4`, `fusion_*.mp4`, `*.log`, `*.res`, `temps_*.txt`) de plus de 24 h, m4a `micro_*.m4a` (dont le m4a de repli) de plus de 7 jours. ffmpeg ne survit pas à l'app : un chien de garde shell, lancé avec lui, vérifie chaque seconde que l'app tourne encore et sinon arrête ffmpeg (SIGTERM, puis SIGKILL après 5 s), y compris après « Forcer à quitter » ou un plantage ; Quitter depuis le Dock ou la déconnexion passent par le même arrêt propre que ⌘Q. Chaque enregistrement micro est en outre limité à 3 h (`-t 10800`) ; au-delà, la vidéo continue sans micro. Le micro est choisi par son nom (validé contre la liste détectée par ffmpeg, passé au shell entre apostrophes) ; l'autorisation macOS « Micro » reste sous le contrôle de l'utilisateur (`NSMicrophoneUsageDescription`). Seule la vidéo du dossier de sortie contient la voix : à ne pas partager sans l'avoir réécoutée. Les vidéos du test automatique (runner) ne reçoivent pas le micro.
- **Données envoyées à l'IA** : le texte de la consigne, les textes affichés à l'écran du téléphone (via `ecran.sh`) et les captures d'écran lues par l'agent sont envoyés à Claude (Anthropic) par Claude Code. N'affichez pas de données sensibles sur le téléphone pendant un test.
- **Token Squash** : enregistré dans le trousseau macOS (service `miroir-telephone-squash`, compte = hôte saisi dans Paramètres, avec le port s'il est saisi), écrit via `security -i` (valeur lue sur l'entrée standard, absente des arguments visibles par `ps`) après validation du format (`[A-Za-z0-9._~+/=-]`, 20 à 2000 caractères). `src/squash.sh` le lit dans le trousseau et le transmet à `curl` par la configuration lue sur l'entrée standard (`curl -K -`) : il n'apparaît dans aucun argument, aucune variable d'environnement, aucun fichier ni journal. **Le token est lié à l'hôte** : si l'adresse change d'hôte, le token de l'ancien hôte n'est jamais envoyé au nouveau, il faut le ressaisir. Un ancien élément au compte `token` (v1.5.0) n'est jamais réutilisé ; il est supprimé à l'enregistrement d'un token ou au clic sur « Effacer » (qui supprime le token de l'adresse enregistrée et de l'adresse saisie si elle est valide). Même limite que pour le PIN : le trousseau est lisible sans invite par les processus de votre session. Utilisez, si possible, un token à droits réduits.
- **Squash en lecture seule** : `squash.sh` refuse toute méthode autre que `GET` et tout chemin hors d'une liste blanche (projets, dossiers de cas, cas de test) ; l'adresse n'a **aucune valeur par défaut** (préférence locale saisie dans Paramètres, jamais dans le dépôt) et doit être en `https://`, avec un nom d'hôte valide (lettres, chiffres, tirets, points ; ni `@`, espace, `?` ni `#`), un port facultatif de 1 à 65535 et un chemin terminé par `/api/rest/latest` (vérifié dans l'app et dans `squash.sh`). Le token est lu au compte de cet hôte : il n'est jamais envoyé à un autre hôte. Les paramètres de requête sont limités à `size`, `page`, `fields` et `sort`, `curl` est lancé avec `-q` (le `~/.curlrc` est ignoré) et sans proxy (`noproxy = "*"`, variables `*_proxy` retirées) : le token ne passe jamais par un proxy hérité de l'environnement, les redirections ne sont pas suivies et les délais sont bornés. Les identifiants de projet, dossier et cas venant de Squash doivent être des entiers positifs sûrs avant de servir à construire un chemin. L'app n'écrit jamais dans Squash. Les réponses temporaires sont écrites dans `~/Library/Caches/MiroirTelephone/squash/` (700) et supprimées après lecture.
- **Contenu des cas Squash = donnée non fiable** : le HTML des cas est converti en texte (balises retirées, entités décodées) puis placé dans la consigne entre les balises `<consigne>` du prompt ; le texte venant de Squash est normalisé (NFKC, caractères invisibles retirés) et tous ses `<` et `>` sont remplacés par `‹` et `›` : aucune balise ne peut survivre. En plus, le prompt délimite la consigne par une balise **à suffixe aléatoire** par exécution (`<consigne-XXXXXXXXXXXXXXXX>`, 16 caractères hexadécimaux tirés de `/dev/urandom`), impossible à deviner par un cas. Le filtre « code / PIN » de la consigne n'est volontairement pas appliqué à ces cas (un cas peut légitimement citer « code APE 1234 ») : un cas hostile peut donc tenter d'orienter l'agent, dans les limites d'outils décrites plus haut. Relisez les cas avant de les rejouer et ne mettez aucun secret dans Squash. Les consignes et rapports sont conservés en clair dans le cache et dans le dossier de sortie (`cas.json`, `rapport.html`, `Campagne_*.html`).
- **Rapports HTML** : tout texte inséré (nom du cas, raison, déroulé de l'agent, consigne) est échappé (`& < > " '`) et la page déclare une politique `default-src 'none'; img-src 'self'; media-src 'self'; style-src 'unsafe-inline'` (aucun script). Les captures et vidéos sont référencées par des chemins relatifs.
- **Variables de test** (`MIROIR_RUNNER`, `DRY_RUN`, `MIROIR_SNAPSHOT*`, `MIROIR_SQUASH_URL`) : elles sont neutralisées par le lanceur du bundle (`unset` avant l'exécution) et `MIROIR_RUNNER` est de plus ignoré par l'app dès qu'elle tourne depuis le bundle. Elles ne servent qu'aux essais depuis les sources.
- **Cache purgé** : au démarrage, les dossiers de `~/Library/Caches/MiroirTelephone/tests/` de plus de 30 jours sont supprimés (uniquement ce dossier), ainsi que les fichiers du micro (temporaires de plus de 24 h, m4a de plus de 7 jours, voir la puce Micro du Mac), uniquement directement sous `~/Library/Caches/MiroirTelephone/micro/` (chemin fixe vérifié, fichiers ordinaires seulement). Le cache `~/Library/Caches/MiroirTelephone/squash/` est purgé de la même façon (fichiers ordinaires de plus de 24 h, sans suivre les liens). Les dossiers de preuves du dossier de sortie ne sont jamais purgés.
- L'app elle-même ne contacte qu'un serveur : celui de Squash, configuré dans Paramètres, en lecture seule via `squash.sh`. Elle ne contient aucun identifiant ni adresse de serveur (l'adresse de Squash est une préférence locale, saisie par l'utilisateur) ; Claude Code, lancé pour un test, communique avec Anthropic.
